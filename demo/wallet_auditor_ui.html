Decepticon Crypto HW Auditor · Interactive Demo

Three tools that run entirely in your browser, offline, against synthetic or paste-in inputs. Models the Coldcard-class TRNG→PRNG silent-fallback incident (2026-07-05, 70 M BTC lost across 1,196 wallets in 41 minutes). No network, no eval, no state persisted.

Ethical framing. This is a defensive audit tool. It scores entropy, seed strength, and firmware version ranges — it never derives real bitcoin addresses and never leaves your machine. The consent-gated PoC for seed enumeration (seed_recovery_poc.py) lives in the source tree and refuses any target that is not owner_consent==true && target_class=="owned_device".

RNG sample scorer

Paste a captured RNG sample as hex or base64 (at least 1 KB recommended). Runs min-entropy Hmin, monobit sigma, longest run, repeated 4-byte block ratio, and catastrophic-block detection — the primary Coldcard signal is repeated_block_ratio > 0.25.

BIP39 seed strength

Score a seed spec against the 128-bit post-Grover target. Raw BIP39 bits + passphrase bits → effective bits → pq-bits (Grover halves brute-force cost). Rule-of-thumb: each cryptographically-random printable-ASCII char = ~5.9 bits.

Firmware version check

Cross-check a vendor + firmware version against the published Coldcard 2026-07-05 vulnerable range. If in-range, rotate any seed generated on this firmware — the range check alone is authoritative regardless of any code-audit finding.

Offline-safe. CSP: default-src 'none'; connect-src 'none'. All computation is inline JS; the sample never leaves your browser. For the consent-gated seed-recovery PoC (owner-only, ethical, never returns seed material), use the CLI helper at packages/decepticon/decepticon/skills/standard/crypto-hw/seed-recovery-poc/seed_recovery_poc.py.
